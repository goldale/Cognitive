Chapter 4

Internal Language

Section 4.6

Implementation Requirements and Open Questions

Release-level requirements

  • The selected internal-language interface must be explicit and versioned.
  • All memory-facing semantic inputs must originate from that interface.
  • Memory serialization must return representations consumable through the corresponding Transformer interface.
  • READ and UPDATE tests must verify use of one shared representation space.
  • Dialogue boundaries and the no-READ first exchange rule must be testable.

Open research questions

  • Which intermediate layer or layer mixture is optimal for each Transformer family?
  • Is a learned stable projection required, and how should it be trained?
  • How should distributed graph state be serialized under a strict sequence budget?
  • How should the system preserve uncertainty and competing associations?
  • How can memory migrate when Transformer weights or architecture change?
  • What empirical tests establish semantic equivalence across READ, UPDATE, and returned serialization?

Architecture versus implementation

The shared-language requirement is canonical. The exact layer, projection, normalization, sequence budget, and injection mechanism remain implementation decisions subject to experimental validation.

RN-0001 — The Babel Hypothesis

Different external symbol systems may express compatible meaning only after reconstruction into a shared internal representation. In Cognitive, this motivates routing external messages through Transformer interpretation before they can participate in memory-facing communication.
