Chapter 10

Associative Memory

Section 10.12

Sequential Multimodal Input Buffer

Input Buffer

The canonical input path contains a modality-neutral Input Buffer between external or internal sources and STM. The buffer is not semantic memory, does not store objects or addresses, and performs no lookup. It temporarily holds a linearly ordered stream of input elements.

Sequencer

The Sequencer is the Input / STM component that orders the combined buffered stream, performs representation normalization required by the input path, proposes Logical Episode boundaries, and prepares the active sequence for STM and associative retrieval. It performs no general reasoning. A dedicated lightweight Transformer may be used internally only as an implementation fallback for difficult boundary cases; this does not create a second architectural Transformer subsystem.

Mutex-protected Input Buffer queue

The Linear / Circular Input Buffer is itself the queue protected by a mutex. Sources enqueue the next available completed input event directly into the next Input Buffer element. The queue does not interpret, prioritize, semantically route, or select destinations.

Linear filling and implicit time

Input Buffer elements are filled sequentially. Their insertion order defines the system-observed temporal order. Time is therefore implicit in buffer position and activation order rather than stored as a timestamp coordinate inside each event.

Warning

Sequential insertion establishes temporal precedence. Causal dependence arises when earlier STM activation contributes to later STM activation. The documentation must not equate mere order with proven external-world causality.

Input Buffer element

Each Input Buffer element is a modality-neutral physical element with a fixed-dimensional activation vector. The current working dimensionality is eight coordinates. The same physical element may be populated at different times from vision, hearing, touch, language, another external source, or an internal source.

[v1, v2, v3, v4, v5, v6, v7, transmission_context]

Transmission Context

One coordinate of the fixed eight-dimensional vector is reserved for service-level transmission context. Its primary role is to preserve the source or mode of the current signal. It does not encode the semantic identity of the observed Item.

Fixed dimensional correspondence

The number of Input Buffer elements equals the number of STM nodes. The vector dimensionality of one Input Buffer element equals the runtime state dimensionality of one STM node. Each buffer element has exactly one permanent physical connection to one corresponding STM node.

|Input Buffer elements| = |STM nodes|; D_buffer_element = D_STM_node; total runtime dimensionality = N × D.

No semantic specialization

Buffer positions and STM nodes do not belong permanently to modalities or Items. A position number identifies only a physical place in the current sequential stream. The transmission-context coordinate carries source information for the current event.

MN-0001 — Alternative parallel input processing

A deferred alternative uses a pool of identical input-processing paths. A free path temporarily connects to a data source, processes one event, publishes the result, and returns to the pool. Parallel completion can reorder observations. More importantly, events from different source streams may belong to the same Logical Episode and may participate in one causal chain. Independent per-stream segmentation can assign such events to different episodes and break cross-stream causal continuity. Because final episode-boundary detection requires the combined context of all relevant streams, this alternative is not canonical. It may be reconsidered only if observation order, processing order, publication order, and cross-stream causal coherence are all preserved.
