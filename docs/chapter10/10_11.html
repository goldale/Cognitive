Chapter 10

Associative Memory

Section 10.11

Semantically Neutral STM and Single Physical LTM

Epistemic status

Working Stage-1 architectural hypothesis. It fixes the present discussion state without claiming that the eventual biological or hardware implementation is already known. Later evidence may revise the hypothesis only through an explicit release-level architectural change.

Single physical LTM with two logical domains

The architecture contains one physical Long-Term Memory vertex and connection array. LTM1 and LTM2 are not separate physical memories. They are orthogonal logical domains implemented through different message types and message-specific state subspaces within the same physical LTM.

LTM1

LTM1 is the semantic logical domain of the single physical LTM. It contains stable Items of the world, basic properties, and a small bounded set of fundamental relations. Examples include chair–sit and bed–lie. In the initial architecture it is treated as effectively immutable, analogous to the initially cloned Transformer.

LTM2

LTM2 is the episodic logical domain of the same physical LTM. It stores completed Logical Episodes through MSG2 while remaining physically co-located with LTM1 and isolated from it by an orthogonal message-specific state subspace.

  • An Item may later acquire a formally defined attribute set.
  • An Item may have more than one basic relation, with an initial working limit of no more than eight.
  • LTM1 does not initially store the personal event sequences generated during operation.
  • LTM1 is not a Vector Database, Knowledge Graph, or GraphRAG system; such mechanisms may support READ only.

Semantically neutral STM

STM contains no objects, labels, addresses, or intrinsic Item attributes. Its nodes are semantically neutral. Meaning arises only through the physical interaction of STM activity with LTM1.

Physical topology of STM

STM is a fixed, fully connected, non-directed physical network. The physical connectivity is not created, deleted, or oriented for each sequence. The state of excitation changes rapidly; the underlying complete connectivity does not.

Sequence

A Sequence is a directed linear activation chain formed within the fully connected STM from the Input Buffer segment identified as one Logical Episode. The Sequencer assigns every active node a position number preserving the original input order.

Identified Input Buffer segment → directed linear STM Sequence
  • A Sequence is not an address chain or a permanently created set of physical links.
  • A Sequence is linear and preserves the observed temporal order of the selected Input Buffer segment.
  • Its direction represents input order, not causal structure.
  • Different Sequences may reuse and overlap the same semantically neutral STM nodes.
  • The Sequence remains active in STM until the completed Logical Episode has been successfully committed to LTM2. After a successful commit, the beginning of the circular input buffer advances to the next Sequence, making the committed Sequence no longer part of STM.

STM–LTM1 projection

Every STM node has one permanent physical projection to an input point of LTM1. This projection is a physical connection, not an address, pointer, identifier lookup, or table-based binding.

STM node excitation → fixed physical projection → LTM1 input excitation → massively parallel propagation and semantic stabilization

During one excitation, each active STM node is associated with semantic content only through the response that its fixed LTM projection participates in producing. The STM node itself does not become a chair, person, action, or other Item and retains no permanent semantic attribute after the excitation ends.

Parallel interpretation

A request excites a distributed linear STM Sequence. Every active Sequence node emits MSG2(amplitude, sequence_number, operation) through its permanent projection to the corresponding LTM input. The complete set of messages constitutes the READ stimulus.

Transformer boundary

The Transformer receives the fixed-dimensional Memory Vector generated from the distributed LTM response. Memory Vector coordinates are intentionally opaque and have no individually prescribed semantics; the Transformer is trained to use the joint pattern.

READ interpretation

READ is not address lookup or retrieval of a selected episode. Every node of the latest STM Sequence emits MSG2(amplitude, sequence_number, operation). MSG2 propagates exclusively through the persistent associative graph stored in LTM1, and the resulting distributed response is reduced to the Memory Vector. READ remains non-mutating.

Single physical LTM

The architecture contains one physical LTM node and connection array. Semantic element processing and completed-episode processing use different message types and orthogonal message-specific state subspaces within that same LTM.

  • What node and connection variables implement the transient linear Sequence without changing physical STM topology?
  • How does the Sequencer estimate Logical Episode boundary confidence?
  • How are concurrent associative waves scheduled and measured in hardware?

Canonical LTM2 READ algorithm

The latest event is represented by the linear STM Sequence produced by the Sequencer. The Sequencer numbers its nodes. Every active node emits MSG2(amplitude, sequence_number, operation) through its permanent STM-to-LTM projection. These messages excite the corresponding LTM inputs and propagate exclusively through the persistent associative graph stored in LTM1. The distributed MSG2 response is then reduced to the fixed-dimensional Memory Vector.

Sequencer chain -> MSG2(amplitude, sequence_number, operation) -> propagation through persistent LTM1 graph -> MAX or SUM readout -> Memory Vector

No independent LTM2 propagation graph

LTM2 does not have its own propagation logic or connectivity. It uses the existing associative structure of LTM1 as its computational substrate while MSG2 state remains isolated in an orthogonal message-specific state subspace.

Persistent-graph invariant

The READ operation never creates temporary associative connections. Every MSG2 propagates exclusively through the persistent associative graph stored in LTM1. Consequently, the generated Memory Vector is a direct consequence of the accumulated associative structure of long-term memory rather than of the current STM event alone.

MSG2 payload

MSG2(amplitude, sequence_number, operation). Amplitude carries STM activation strength. sequence_number carries the local position already assigned to the STM node. operation is interpreted locally by the receiving LTM1 node and initially supports READ and UPDATE. The target atom is supplied by the permanent STM-to-LTM projection rather than encoded as an address.

  • Reset the fixed Memory Vector output cells.
  • Number all nodes of the latest linear STM Sequence.
  • Every active Sequence node emits MSG2(amplitude, sequence_number, READ).
  • Inject each message through the permanent projection to its corresponding LTM input.
  • Propagate every MSG2 exclusively through the persistent LTM1 associative graph.
  • Reduce the distributed response into Memory Vector cells using MAX or SUM.
  • Return the Memory Vector and clear transient MSG2 excitation.

Information-preserving readout selection

The initial implementation supports both MAX and SUM readout operators without assuming either is optimal. Under deterministic READ, both are evaluated on identical representative LTM states and Event Queries, and the operator producing the higher non-degenerate Memory Vector entropy is preferred. If READ becomes stochastic, mutual information must be used to distinguish memory-dependent information from internally generated noise.

Per-message operation

READ and UPDATE are operations carried inside each MSG2, not global STM modes. Different STM nodes may therefore emit READ and UPDATE operations concurrently. The receiving LTM1 node interprets the operation locally.

Single MSG2 start mechanism

STM-node activation is the only mechanism that emits MSG2. No Transformer, Sequencer, UPDATE engine, or LTM component may inject MSG2 directly.

UPDATE through associative match

An UPDATE MSG2 first excites its LTM1 candidate and propagates through the same persistent LTM1 graph as READ. It requests associative matching; it does not directly authorize an LTM2 write. Only a confirmed associative match may mark the resolved LTM1 atom as participating in the LTM2 update.

Context for associative match

Context is one or two existing LTM1 links used to constrain the match of the candidate object. It is not a large independent embedding or a separate memory object.

Transformer UPDATE path

Transformer directly constructs the STM chains used for UPDATE from LTM1 associative atoms and a minimal structural-link alphabet. Their starts, ends, order, previous, next, and context are already determined; the Sequencer is not invoked.

Native LTM1 language export

LTM1 and Memory Vector jointly provide the native communication language used by Transformer. A deterministic external procedure selectively exposes LTM1 associative atoms and obtains repeated MAX or SUM readouts. The resulting Memory Vector sequence exports those atoms to Transformer. This is a language-generation and communication procedure, not a requirement to serialize the complete state of LTM1.
