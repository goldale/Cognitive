Chapter 10

Associative Memory

Section 10.14

Directed Episode Graph Storage and Connection Trace Lists

Canonical scope

This section describes storage and retrieval of completed compositions. Section 10.1 is canonical for the Dialogue-aware READ/UPDATE cycle and shared internal-language serialization; Section 10.15 is canonical for local MSG2 interpretation and match-gated LTM2 write.

Single physical LTM

LTM is one physical array of interacting memory vertices and connections. Semantic element processing and completed-episode processing are not separate physical memories; they are distinct message-mediated processes operating in orthogonal state subspaces of the same LTM.

Message types and orthogonal state

MSG1 — Element-semantic message

MSG1 carries the element-level activation used for semantic interpretation and associative processing before a completed Logical Episode is available. It activates only the MSG1 state subspace of each participating LTM vertex and connection.

MSG2 — STM-emitted operation message

MSG2(amplitude, sequence_number, operation) is emitted only by STM-node activation. The operation is READ or UPDATE and is interpreted locally by the receiving LTM1 node. The message does not carry a complete graph or authorize an immediate LTM2 write.

Orthogonal message-specific state subspaces

The internal state of every LTM vertex and participating connection is partitioned into orthogonal message-specific state subspaces. Processing one message type activates and updates only its corresponding subspace; the orthogonal subspaces remain unaffected.

Shared LTM1 propagation

READ and UPDATE MSG2 may propagate concurrently and coexist, but both excite and propagate exclusively through the same persistent LTM1 associative graph. Operation-specific local effects remain distinguishable without creating an independent propagation graph.

one physical LTM = persistent LTM1 propagation substrate + operation-marked transient state + LTM2 matched compositions

Connection-allocation cost

In hardware, allocating a new direct logical connection is a fast switch reconfiguration rather than slow biological growth. In this limited engineering sense, connection formation does not distinguish short-lived from long-lived memory; persistence policy remains separate.

Episode representation

Sequence to episode graph transformation

Sequence determines episode vertices

A completed linear STM Sequence determines which vertices participate in one Logical Episode. The Sequence preserves temporal input order but does not define causal topology.

Per-element Transformer output

After a Logical Episode is completed, the Transformer produces one context-dependent data vector for every participating element. It does not replace those vectors with one vector for the complete episode.

v(i,g) = Transformer(element i in complete episode context g)

Single full-data copy

The complete vector for an episode element is stored exactly once, in the corresponding vertex of the stored episode graph. Semantic Items, search traces, and causal edges must not duplicate that full vector.

Causal orientation

The orientation of the stored graph expresses causality within the episode. It is independent of physical conductor orientation and independent of the direction in which an activation currently propagates.

Transformer-defined graph topology

Transformer constructs completed STM chains from internal-language representations. Starts, ends, order, context, previous, and next are determined during processing, so the Sequencer is not invoked during UPDATE.

Connection-local Trace Lists

Trace List

The list of independently matchable local trace structures stored on one physical LTM connection within a message-specific state subspace. Associative search is performed only over the Trace Lists belonging to the active message type.

Connection(e) = Physical Channel(e) + Trace List(e)
Trace List(e) = [trace₁, trace₂, …, traceₙ]

Exclusive associative-search domain

At each search step, the current activation is compared only with entries in the connection-local Trace Lists of the active message-specific subspace. No global graph index, episode lookup, address resolution, or cross-subspace matching participates in the cognitive search operation.

Minimal Semantic Search Trace

The smallest connection-local associative discriminator sufficient to decide whether the current activation may cross that connection. Its physical placement already identifies the possible transition.

  • Item, target, graph, and episode addresses or identifiers.
  • A stored multi-hop route.
  • A special initial search-signal state.
  • The complete Transformer-produced vector of an episode element.
  • A duplicate of graph structure or causal neighbours.

Sequential associative retrieval

  • Activation reaches an Item.
  • Trace Lists on available connections are compared with the current activation.
  • A compatible Trace permits transition through its physical connection.
  • The same comparison and transition operation repeats at the next Item.
  • Retrieval terminates when the corresponding full episode-graph vertex is reached.
Trace-list match → transition → Trace-list match → transition → … → full graph vertex

Search from an element

Retrieval begins from a semantic element together with available context and temporal constraints. The system finds an episode through that element; it does not first identify an episode as a globally addressable object.

Progressive Virtual Contraction

Fixed origin and advancing endpoint

During semantic search, the origin remains fixed and the temporary virtual endpoint is replaced after every successful transition.

A → A—X₁ → A—X₂ → A—X₃ → A—B

One final reconfiguration

The complete multi-hop semantic-search path is never stored as a persistent memory structure. Intermediate contractions are virtual and do not reconfigure the multiplexer. After the target is reached, one switch-fabric operation may materialize the direct logical connection between the surviving endpoints.

Hardware interpretation

A multi-hop sequence is a transient artifact of semantic search. In present-day hardware, creating the final direct logical connection is a fast and inexpensive switch reconfiguration; persistent multi-hop storage is not an alternative architecture.

Directed graph storage

  • One full per-element vector in each episode-graph vertex.
  • Causal relations among those vertices.
  • Connection-local Trace Lists that support associative entry and repeated local transition.

No duplicated graph object

The directed graph is not duplicated in a global graph store for retrieval. It is reconstructed from its full vertices, causal relations, and the connection-local traces that make those vertices reachable associatively.

Scale and forgetting

Trace-list growth

Exact distinguishable history can create extremely large Trace Lists. This is the direct storage cost of retaining oriented causal graphs that remain accessible by associative search from their elements.

Transformer-dependent forgetting

Local statistics may identify candidates, but semantic forgetting cannot be completed without the Transformer. Candidate graphs must be reconstructed and semantically evaluated before traces, causal relations, or vertices are weakened, consolidated, partially removed, or deleted.

  • Retain semantically important or unique history.
  • Weaken low-priority access without immediate destruction.
  • Consolidate repeated graphs while preserving meaningful differences.
  • Remove dispensable detail without breaking retained causal structure.
  • Delete a graph and its unique access traces only after consistency checks.

Open implementation questions

  • Exact encoding and dimensionality of one minimal associative discriminator.
  • Matching thresholds and ambiguity resolution inside long Trace Lists.
  • Ordered versus unordered logical semantics of a Trace List.
  • Hardware acceleration and tiering without changing the cognitive search contract.
  • Representation of causal relation state.
  • Safe sharing of common search prefixes and traces.
  • Consistency-preserving Transformer-guided forgetting and consolidation.
  • Capacity, latency, interference, and failure-mode benchmarks.

MN-0002 — Compressed or superposed Trace storage

Status: Deferred. Compression, superposition, indexing, and storage tiering may be investigated as physical optimizations only if they preserve the Section 10.14 retrieval contract and retained-history distinguishability.
