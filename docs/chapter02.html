Chapter 2

The Central Idea

2.1 The Central Idea

Cognitive separates deep Transformer cognition from persistent long-term associative memory while allowing both to operate in one shared latent Internal Language.

Principle

Long-term memory is not queried through natural language, JSON, symbolic commands, or an external retrieval protocol. Transformer and Associative Memory exchange native latent READ and UPDATE activations in the Transformer-defined Internal Language.

  • Transformer performs cognitive processing.
  • Associative Memory preserves and retrieves long-term experience.
  • READ and UPDATE are internal latent interactions, not external messages.
  • D-Context exists only inside Associative Memory and makes later Dialogue retrieval possible.

Principle

A technically competent new reader should be able to explain the central innovation after reading the first ten pages.

2.2 Why Textual Memory Interfaces Are Limiting

Conventional retrieval pipelines commonly translate model state into text or symbolic queries, search an external store, and translate the result back into model context. That interface discards information already present in the model hidden state and makes memory appear as an external application.

Cognitive instead treats a selected intermediate Transformer representation as the basis of an endogenous Internal Language. Associative Memory learns in that space from the beginning.

Not RAG with different terminology

The architecture is not defined by a text retriever attached to an LLM. Its distinguishing mechanism is the native latent coupling between Transformer processing and persistent associative memory.

2.3 The Latent Memory Interface

Internal Latent Interface

The Transformer-facing neural interface through which UPDATE exports an internal latent state to Associative Memory and READ reinjects a memory-derived latent response into Transformer processing.

UPDATE

A native latent interaction that exposes a Transformer-produced internal state to Associative Memory for learning and D-Context evolution.

READ

A native latent interaction that returns a memory-derived internal representation to Transformer processing when an established D-Context makes retrieval meaningful.

First-exchange rule

The first exchange of a new Dialogue produces no READ because Associative Memory has no D-Context for that Dialogue. The first UPDATE establishes it.

Interface semantics

READ and UPDATE must not be drawn or described as network requests, textual commands, JSON messages, or an external message bus.

2.4 The Physical Architecture

The canonical physical architecture contains a Transformer Cognitive Core and Associative Memory. STM, LTM1, exists.

Research Proposal — Layer N with dual-width organization

Draft 05 presents a selected intermediate Layer N with distinct UPDATE and READ capacity as the leading implementation proposal. The exact layer depth, width expansion, channel partitioning, extraction point, reinjection point, and fusion mechanism remain subjects for RS-0011 discussion.

2.5 What Is Not a Separate Module

Reasoning, Planning, Temporal Organization, Semantic Representation, and Integrated Evaluation describe cognitive functions or observable processing responsibilities. They do not imply independent code modules, services, parsers, or symbolic engines.

Physical-versus-functional rule

A function may appear as a chapter and may be experimentally isolated, but it must not be rendered as a separate physical component unless the canonical architecture explicitly assigns it an independent implementation boundary.

2.6 Epistemic Status and Research Proposals

Canonical Architecture

A frozen architectural decision that subsequent documentation and diagrams must preserve.

Research Proposal

A concrete leading design presented to make the architecture understandable and testable, but explicitly marked for further discussion before final freeze.

Open Question

A mechanism whose role or implementation is not yet sufficiently determined.

Research Proposal — LTM1 Associative Vector Codebook

Draft 05 adopts LTM1 Associative Vector Codebook as the preferred name for the proposed latent indexing structure associated with LTM1. It may use learned code vectors, latent quantization, approximate associative matching, or another mechanism.

Open Question — Codebook mechanics

The exact operation of the LTM1 Associative Vector Codebook as a separate indexing structure remains to be discussed. Its relation to LTM1 vertices, edge lists, logical domains LTM1/LTM2, candidate generation, quantization, collision handling, learning, and retrieval has not yet been canonically fixed.

Research Proposal — dual-width latent layer

A double-width intermediate representation with one UPDATE-oriented channel and one READ-oriented channel is the leading explanatory and implementation proposal. Its exact realization remains open for RS-0011.
