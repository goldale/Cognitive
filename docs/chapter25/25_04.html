Chapter 25

Documentation Architecture

Section 25.4

Generation and Validation Rules

DA-0006 — Automatic Generation

The generator creates navigation, HTML anchors, typed registries, A–Z entries, cross-references, and future LaTeX output for the complete documentation from canonical data. PDF is not a primary generated documentation format; when required, it may be produced explicitly by compiling the generated LaTeX.

  • Every typed object must have a unique identifier.
  • Every internal reference must resolve.
  • Generated HTML must expose a stable anchor for each typed object.
  • Complete-document typesetting output must be generated as LaTeX; PDF compilation is optional and explicit.
  • Generated LaTeX is text-based and must be retained in Git so documentation changes remain diffable and reviewable; derived PDF output is not retained as the standard versioned documentation artifact.
  • Registries list canonical objects without duplicating their full text.
  • Human readability has priority over excessive formalization.
  • Release validation must detect duplicate identifiers and broken references.

Future releases may represent the canonical documentation as an explicit graph of objects and relations while preserving the current human-readable chapter structure.

DA-0007 — Git is the version authority

Canonical YAML, generated HTML, and generated LaTeX are version-independent. Their content must not contain release, version, revision, build-number, or schema-version metadata used only to identify a project snapshot. Git commits and tags provide the authoritative history.

  • A release archive name may identify a packaged snapshot.
  • Changing only a release number must never require editing architectural YAML or regenerated HTML.
  • Generators and bootstrap scripts must not insert version labels into canonical YAML, HTML, or LaTeX.
  • Tests must reject reintroduction of version metadata into canonical YAML, generated HTML, and generated LaTeX.
  • Package-manager metadata may retain its own technical package version when required by the packaging ecosystem; it is not architectural documentation.
